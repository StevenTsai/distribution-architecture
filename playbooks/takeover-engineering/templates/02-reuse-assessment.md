## 一、评估口径

### 1.1 四分类定义

| 分类 | 判定标准 | 允许的结论 |
|---|---|---|
| **完整复用** | 功能、交互、验收标准均满足；只需回归验证 | 不产生开发人日，仅测试人日 |
| **部分复用** | 主体结构/逻辑可留，但需改造、补测、补契约或补兼容 | 按改造点估算 |
| **纯新增** | 存量中没有，或虽有但不可用 | 按新功能估算 |
| **待确认** | 证据不足，或需客户/第三方确认 | 不计入承诺，列入风险准备金 |

### 1.2 证据等级

| 等级 | 判定 | 对分类的影响 |
|---|---|---|
| E1 源码实证 | 读到实现并能定位 | 可判完整/部分复用 |
| E2 运行实证 | 可复现跑通/抓包 | 可判完整/部分复用 |
| E3 文档/契约 | 有书面依据但未验证 | 最高只能判「部分复用（待验证）」 |
| E4 推断 | 从行为/命名反推 | 只能判「待确认」 |
| E5 假设 | 口头/全新 | 只能判「待确认」或「纯新增」 |

> **硬规则：没有 E1/E2 的项，不得标记为「完整复用」。**

## 三、评估方法

### 3.1 静态走查（对应 E1）

1. 先看目录结构与依赖，判断技术栈与工程完整度；
2. 再看入口与路由，列出全部界面/接口；
3. 对每个单元定位实现，记录文件与行号；
4. 标记死代码、注释掉的逻辑、硬编码、TODO/FIXME；
5. 检查是否有「只在演示环境生效」的分支。

### 3.2 构建与运行验证（对应 E2）

1. 从零克隆，按 README 构建，记录耗时与失败点；
2. 若构建失败，记录缺失依赖/私有包/环境变量；
3. 能运行时，跑主链路，抓取实际请求与响应；
4. 对比「代码行为」与「文档描述」，差异记入台账。

### 3.3 契约核对（对应 E1–E3）

1. 以**客户端实际消费**为准，不以文档为准；
2. 逐字段核对：字段名、类型、可空、枚举、错误码、分页；
3. 记录客户端「依赖但文档未写」的隐式契约；
4. 无法核对的，标 E4/待确认。

### 3.4 对比法（适用于有截图/旧系统的场景）

1. 按界面状态逐一对照；
2. 记录「视觉一致但逻辑不同」「逻辑一致但文案不同」；
3. 文案与枚举顺序可能被客户端按字符串分支，不能擅自改。

## 五、与报价的衔接

```
增量报价 = Σ(部分复用改造人日)
         + Σ(纯新增人日)
         + Σ(联调/测试人日)
         + 风险准备金（待确认项 × 系数）
         + 外部依赖成本
```

**纪律**：

1. 每个数字能追溯到本表的行；
2. 待确认项不得按「乐观值」计入，必须单列；
3. 完整复用也要计回归测试人日，不能记 0；
4. 报价附「假设清单」，假设变化触发重算；
5. 不把「复用」当成「免费」——复用的成本是理解、验证与回归。

## 八、常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 按页面粗粒度评估 | 低估交互与状态组合 | 拆到「界面状态/接口」 |
| 把「代码存在」当「功能可用」 | 后期返工 | 必须有 E1/E2 运行验证 |
| 忽略隐式契约 | 联调阶段爆炸 | 以客户端消费为准逐字段核对 |
| 待确认项按乐观值计入 | 报价失真 | 单列风险准备金 |
| 完整复用不计测试 | 回归出事故 | 至少计回归人日 |
| 评估人同时是报价人 | 倾向乐观 | 评估与定价分离，或引入复核 |
