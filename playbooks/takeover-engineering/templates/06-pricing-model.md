# 模板 06｜增量报价模型

> **阶段**：定价 ｜ **用途**：把「接手一个存量系统还要做多少」换算成可审计、可解释、可重算的价格 ｜ **版本**：v0.2
> **前置**：已完成 `templates/02-reuse-assessment.md` 与 `templates/03-gap-risk-ledger.md`。
> **原则**：报价不是数字，是**一组假设的价格**。假设变了，价格必须能重算。

---

## 一、报价的五块结构

```
报价 = ① 基础交付（可审计人日）
     + ② 存量改造（按复用度四分类逐项）
     + ③ 纯新增（按模块逐项）
     + ④ 风险准备金（E4/E5 与外部依赖）
     + ⑤ 外部成本（设备、账号、第三方、差旅）
```

**不含在报价里的东西，必须单独列出**：税费、平台费用、第三方订阅、硬件采购、加急成本、维护期费用。

---

## 二、输入清单

报价前必须拿到以下输入。缺一项，对应部分只能给区间或标注「待确认」。

| # | 输入 | 来源 | 缺失时的处理 |
|---|---|---|---|
| 1 | 可独立验收的单元清单 | 02 逐项表 | 不给固定价 |
| 2 | 每单元复用分类 | 02 | 按「纯新增」上限估算 |
| 3 | 每单元改造点 | 02 | 列入待确认 |
| 4 | 缺口与风险台账 | 03 | 无法计风险准备金 |
| 5 | 软硬件边界矩阵 | 04 | 无法排除非软件工作 |
| 6 | 验收标准 | 01 / 合同 | 不给固定总价 |
| 7 | 人天单价与费率 | 商务 | 只出人日，不出金额 |
| 8 | 外部依赖报价 | 第三方/采购 | 单列，不含在总价 |

## 三、模块拆分规则

### 3.1 拆分原则

1. **可独立验收**：一个模块能单独演示、单独测试、单独签字；
2. **可独立估算**：一个人能在不依赖其他模块细节的情况下估出人日；
3. **可独立变更**：需求变化时，只影响一个模块的价格；
4. **不按文件拆**：文件是实现的副产物，不是报价单元；
5. **不按页面粗拆**：一个页面可能包含 5 个状态和 3 个接口，粗拆会漏工。

### 3.2 推荐层级

```
系统
└── 端（小程序 / App / Web / 后端 / 管理端）
    └── 模块（登录、设备、订单、报表…）
        └── 单元（界面状态 / 接口 / 业务规则 / 集成）
```

报价至少落到**单元**，汇总到**模块**。

## 四、人日估算

### 4.1 三点估算

对每个单元给出乐观 / 最可能 / 悲观三个值：

```
期望人日 E = (O + 4M + P) / 6
标准差  SD = (P − O) / 6
```

| 单元 | O | M | P | E | SD | 说明 |
|---|---:|---:|---:|---:|---:|---|
| <span v-pre>{{U-01}}</span> | | | | | | |
| <span v-pre>{{U-02}}</span> | | | | | | |

**使用规则**：

- 单个单元 P/O > 3 时，说明理解不足，先补证据，不要直接报；
- 模块合计用 ΣE，不用 ΣM；
- 总标准差用于判断是否需要风险准备金（见 §六）。

### 4.2 人日包含什么

| 包含 | 不包含（单列） |
|---|---|
| 编码 | 需求澄清会议 |
| 自测 | 与第三方联调 |
| 代码审查修改 | 真机/现场测试 |
| 文档更新 | 部署与上线值守 |
| 单元测试 | 性能/安全专项测试 |

> **最常见的低估**：把联调、真机、部署、返工当成「顺手做掉」。这些必须单列。

### 4.3 效率修正

| 因素 | 系数 | 说明 |
|---|---:|---|
| 熟悉技术栈 | 1.0 | 基准 |
| 部分熟悉 | 1.2–1.3 | 需要查文档与试错 |
| 不熟悉 | 1.5–2.0 | 学习成本 + 返工 |
| 代码质量差 | 1.2–1.5 | 理解与绕行成本 |
| 无文档 | 1.2–1.4 | 反推成本 |
| 多端联调 | 1.2–1.5 | 沟通与等待 |
| 外部依赖不可控 | 1.3–2.0 | 阻塞与重试 |

系数相乘后，应回写为「调整后人日」，并注明乘了哪些系数。

## 五、存量改造计价

| 分类 | 计价方式 | 说明 |
|---|---|---|
| 完整复用 | 只计回归人日 | 不按 0 计；理解与验证也是成本 |
| 部分复用 | 改造点人日 + 回归人日 | 逐项列改造动作 |
| 纯新增 | 按新功能三点估算 | 不与存量混算 |
| 待确认 | 不计入承诺价 | 单列区间或风险准备金 |

**改造人日的三个常见漏项**：

1. **兼容成本**：旧数据、旧接口、旧客户端；
2. **回归成本**：改一处，测一片；
3. **清理成本**：死代码、临时开关、历史补丁。

## 六、风险准备金

### 6.1 计算

```
风险准备金 = Σ(待确认项预估人日 × 不确定性系数)
           + Σ(E4/E5 项 × 暴露系数)
           + 外部依赖延误成本
```

| 不确定性 | 系数 | 适用 |
|---|---:|---|
| 低（有间接证据） | 0.2–0.3 | E4，但结构可推断 |
| 中（证据薄弱） | 0.4–0.6 | E4/E5，需调研 |
| 高（几乎未知） | 0.8–1.0 | E5，可能需要重做 |

### 6.2 准备金的使用规则

1. 准备金**单列**，不摊进模块单价；
2. 使用时需记录「消耗在哪一项」；
3. 未使用部分是否退还未定，必须在合同中写明；
4. 准备金不是利润，不能计入毛利率。

## 七、外部成本

| 类别 | 示例 | 计价方式 | 谁承担 |
|---|---|---|---|
| 设备/样机 | 测试机、传感器、网关 | 采购价 + 损耗 | 通常客户 |
| 账号/资质 | 平台认证、短信、地图 | 实报实销或预估 | 客户 |
| 第三方服务 | 云资源、OCR、推送 | 按量或包年 | 客户 |
| 差旅/现场 | 部署、真机联调 | 按次/按天 | 客户 |
| 加急 | 压缩工期 | 加价系数 | 客户 |

**纪律**：外部成本不进入人天单价，避免「用人力利润补贴采购」。

## 九、变更计价

```
变更价格 = 新增/修改单元人日 × 单价
         + 回归影响人日 × 单价
         + 已发生的外部成本
         + 加急系数（如适用）
```

**变更规则必须写进合同**：

1. 口头变更无效；
2. 变更单需写明范围、人日、金额、对工期的影响；
3. 双方确认后生效；
4. 累计变更超过合同价 <span v-pre>{{X}}</span>% 时，触发重新评审；
5. 变更导致原计划作废的，已投入人日按实际结算。

---

## 十、报价纪律

1. **每个数字可追溯到行**：总价 → 模块 → 单元 → 改造点；
2. **不报「一口价」**：除非范围、验收、假设都已冻结；
3. **不把待确认项按乐观值计入**；
4. **不承诺「做完再说钱」**；
5. **不把风险准备金藏进单价**；
6. **价格有有效期**：<span v-pre>{{30/60/90}}</span> 天，逾期重算；
7. **报价与评估分离**：评估人不得单独决定最终价格。

---

## 十一、质量检查清单

- [ ] 每个模块可独立验收；
- [ ] 每个单元有人日与依据；
- [ ] 待确认项单列，未计入承诺价；
- [ ] 联调、真机、部署、回归已单列；
- [ ] 风险准备金有计算过程；
- [ ] 外部成本单列，未混入人天；
- [ ] 假设清单完整，且写明不成立的影响；
- [ ] 变更计价规则可执行；
- [ ] 价格有效期与付款节点明确；
- [ ] 总价与明细可自动对账（求和一致）。

---

## 十二、常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 按页面报价 | 漏状态、漏接口 | 拆到单元 |
| 复用不计回归 | 上线回归出事故 | 完整复用也计测试人日 |
| 待确认按乐观值 | 报价失真 | 单列准备金 |
| 风险准备金摊进单价 | 无法解释、无法结算 | 单列 |
| 外部成本混入人天 | 利润被采购吃掉 | 单列实报实销 |
| 没有假设清单 | 变更时无法重算 | 每条假设写影响 |
| 报价无有效期 | 几个月后仍被引用 | 写明有效期 |
| 评估与定价同一人 | 系统性乐观 | 分离或复核 |
