# 01｜签约前投入纪律（杠杆不对等复盘）

> **版本**：v0.1 ｜ **日期**：2026-10-24 ｜ **状态**：已随本仓库发布
> **定位**：「止损前置」原则在**商务侧**的补丁。模板 05 解决"什么时候停"，本文解决一个更前置的问题——**签约前，投入本身需要被管理**。
> **来源**：抽象自私有项目 2026-09～10 一次软硬一体项目的真实经历：技术探路启动过早、投入持续滑坡，代码近完成时合同仍未落纸，项目最终终止。已去除客户名称、品牌、金额与绝对时间锚点。

---

## 一、一句话结论

**对外的限期文件只约束了对方的答复，没有约束自己的投入增速。**

对方在限期内沉默，成本为零；我方在限期内"边谈边做"，成本按人日累积。当两条曲线叉开时，"限期确认"不会形成止损，只会制造一种"风险已在管控"的错觉——真正的止损杠杆从来没有架在自己这一侧。

---

## 二、事实模型

泛化时间线（相对刻度，不含真实日期）：

| 时刻 | 事件 | 我方投入状态 |
|---|---|---|
| T0 | 立《承接确认单》：资产/授权/商务三件套，限期 <span v-pre>{{N}}</span> 个工作日答复 | ≈0 |
| T0+起始 | 担心首次做该类项目、工期不可估 →「边谈边搭框架」启动 | 开始累积 |
| T0+<span v-pre>{{N}}</span> | 期限届满，未获正面答复 | 框架已成形；**无"停/续"决策记录** |
| T0+<span v-pre>{{N}}</span>+x | 等待继续，投入从"框架"滑向"近完整实现" | **学费大头发生在此** |
| T1 | 合同落纸（晚于投入曲线） | 已沉没大半 |
| T2 | 项目终止；权利归属存疑时，案例化变现也要打折 | 学费结算 |

**学费的主构成不是"白做"，而是叉开天数 × 每日投入。** 这两个变量都握在自己手里，不在对方手里。

---

## 三、机制：为什么正确的动作会走样

用代码消解估算风险（可行性逆向、关键依赖验证）本身是对的——首次做某类项目时这是合理的风险动作。走样发生在四个机制叠加之后：

1. **"框架"没有完成判据**——框架与实现之间是连续滑坡，没有一条线说"到这里停"；
2. **沉没成本接管决策**——写到 30% 时，"继续写"的边际成本在心理上低于"白等"，虽然账面上恰恰相反；
3. **对方获得免费观察窗口**——投入越多，对方"反正已经做了，不签也不亏"的位置越好，我方议价位置越差；
4. **限期文件制造管控错觉**——文件只写了对甲方的要求，没写对自己的约束，于是"我们在等答复"成为继续投入的正当理由。

一句话：**焦虑推动了探路，但没有任何机制在探路完成后叫停。**

## 四、五条规则（操作化）

### R1 探路必须 time-box

- spike 启动前写明：**截止日 + 一页纸结论的交付形式 + 完成判据**；
- 到期必须做"停 / 续"决策；续期需要书面理由并重新设定上限；
- spike 的产出是**可行性判断**，不是可交付代码——代码是副产品，不是目标。

### R2 投入分级封顶

| 级别 | 允许条件 | 授权人 | 上限 | 允许的产出 |
|---|---|---|---|---|
| L0 观察 | 对接首日起 | 自己 | <span v-pre>{{X}}</span> 人日 | 问题清单 + 初步判断 |
| L1 探路 spike | 对方有明确意向表达 | 自己 | <span v-pre>{{Y}}</span> 人日 | 一页可行性结论 |
| L2 框架 | 确认单获**正面**答复 | 自己/合伙人 | <span v-pre>{{Z}}</span> 人日 | 可运行骨架（不含业务实现） |
| L3 实现 | **合同落纸 + 首款到账** | 合同 | 按里程碑 | 交付物 |

超限即升级：要么拿到新授权，要么停在当前级别。**没有"这次特殊"**——"这次特殊"就是滑坡的第一句话。

### R3 杠杆对称原则

任何对外的限期文件（确认单、三件套、答复函），**必须在同一天配上对内的投入上限**，两者写进同一份文件的两个 section：

- **对甲方**：答复内容 + 期限 + 逾期后果；
- **对自己**：本阶段投入封顶 <span v-pre>{{X}}</span> 人日；期限届满时自动执行的动作（引用模板 05 的分级）。

只约束对方的止损文件，是半成品。

### R4 筹码保留：进度 ≠ 交付物

- 代码进度用于**展示能力**（"我做过，这是能跑的"），不用于**免费打样**；
- 真机联调、固件侧配合、生产账号/密钥接入、验收支持——**只在签约后释放**；
- 对外永远留一块"只有签约才能拿到的东西"。技术方在软硬一体项目里天然弱势（设备、账号、验收解释权都在对方），筹码保留是唯一的对冲。

### R5 期限届满 = 止损触发，不是"再等等"

确认单到期未获正面答复，**自动**进入模板 05 的止损判定（默认"观察→暂停"），而不是"再等两周"的起点。触发后必须留下决策记录；如果决定继续，那是一次**新的、有上限的**授权，不是惯性延续。

## 五、投入升级路径（闸门图）

```
L0 观察 ──意向──▶ L1 探路 spike ──确认单正面答复──▶ L2 框架 ──合同落纸+首款──▶ L3 实现
   │                  │                  │                  │
   └ 产出:问题清单     └ 产出:一页结论     └ 产出:可运行骨架   └ 产出:里程碑交付
   上限:{{X}}人日      上限:{{Y}}人日      上限:{{Z}}人日      按合同
```

**L2 → L3 的唯一通行证是合同落纸（或等价书面承诺 + 首款）。**「先做着，合同在走流程」= 未通过闸门。流程走多久都不改变这条规则——流程是对方的内部事务，不是我方投入的理由。

## 七、常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 把"框架"当无限额阶段 | 滑坡主发生地 | L2 有硬上限，超限即停 |
| 限期文件只写对甲方的要求 | 假止损 | R3：同文件配对内上限 |
| "合同在走流程"期间继续实现 | 投入无闸门 | L2→L3 唯一通行证规则 |
| 把 spike 代码直接当交付物起点 | 沉没成本绑架谈判 | spike 产出是结论，代码默认可弃 |
| 对外展示完整演示，不留签约后交付物 | 免费打样，议价恶化 | R4 筹码保留 |
| 期限届满后"再等两周" | 惯性延续，无决策记录 | R5：到期即触发，续期 = 新授权 |
| 探路成本报价时说不清 | 或丢单或亏售前 | 模板 06 假设清单显式声明 |

## 八、复盘模板（签约前投入专项）

```
签约前投入复盘
1. 时间线
   - 确认单发出日 / 届满日 / 合同落纸日 / 终止日
   - 每周投入人日曲线（与上述四个日期叠在同一张图）
2. 叉开天数与学费
   - 叉开天数 = 合同落纸日 − 投入起始日（若先触发止损，取触发日）
   - 学费 ≈ 叉开天数内投入人日 × 单位成本
3. 闸门复盘
   - L0→L1→L2 每一级的触发依据是什么？有无书面记录？
   - 哪一级没有拦住？当时"这次特殊"的原话是什么？
4. 机制改进
   - 哪条规则（R1–R5）应新增/修改数字？
   - 模板 05 的哪条触发条件本应命中却没被识别？
5. 下一次的前置条件
   - 本类项目的 L1/L2 封顶数字重估（能力已具备，探路成本应显著下降）
```

## 九、一页速查

```
【探路前】
□ spike 有截止日 + 完成判据 + 一页纸结论形式
□ 投入级别（L0/L1/L2）已判定，封顶数字已填

【对外发文件时】
□ 同日配对内投入上限（R3 杠杆对称）
□ 逾期动作已写明（引用模板 05 分级）

【每个闸门】
□ L1→L2：确认单获正面答复？（沉默 ≠ 答复）
□ L2→L3：合同落纸 + 首款？（"流程中" ≠ 落纸）
□ 超限：停 / 新授权，留书面记录

【期限届满】
□ 自动触发止损判定，不留"再等等"选项
□ 续期 = 新一级授权，重新设上限

【对外展示】
□ 进度用于展示，不用于打样
□ 真机/固件/账号/验收支持 = 签约后释放物
```
