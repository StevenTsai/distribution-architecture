# 模板 04：容量与演练

> **能力域**：演练 ｜ **配套**：[00 方法论 §六](../00-methodology.md) ｜ **产出**：容量模型 + 压测报告 + 演练计划与复盘

---

## 一、容量模型

### 1.1 输入

| 项 | 取数 | 说明 |
|---|---|---|
| 峰值基线 | 近 12 个月峰值 | 取业务真实峰值，不取均值 |
| 增长率 | 同比/环比 | 保守取高值 |
| 余量系数 | 建议 1.5–2.5 倍 | 越高越稳，成本越高；按业务容忍度定 |
| 单点容量 | 压测实测 | 单实例能扛多少，不靠估算 |

### 1.2 输出：瓶颈排序表

| 组件 | 当前峰值使用率 | 单点容量 | 余量倍数 | 预计见底时间 | 优先级 |
|---|---:|---:|---:|---|---|
| 订单库主库 | 45% | __ QPS | 2.2x | 2028-Q1 | P2 |
| 消息队列 | 70% | __ msg/s | 1.4x | 2027-Q2 | **P1** |
| 缓存集群 | 55% | __ ops/s | 1.8x | 2027-Q4 | P2 |

见底时间 = 按增长率外推的第一次超限时间。**P1 标准：见底时间早于下一次大促/扩容窗口**。

## 二、压测方案

| 类型 | 目的 | 做法 | 通过标准（示例） |
|---|---|---|---|
| 基准压测 | 找到单点容量基线 | 逐步加压至错误率上升 | 记录拐点 QPS 与资源水位 |
| 峰值压测 | 验证业务峰值承载力 | 按峰值 × 余量系数施加 | 错误率 < __%，P99 < __ms |
| 破坏性压测 | 验证超载行为 | 压到系统崩溃 | **优雅降级而非雪崩**；限流生效 |

三条纪律：

- **压测走变更流程**（要通知、要观察、要有回滚）；
- **压测环境与生产同构**（至少数据量与配置同构），否则结论不可信；
- **压测报告必须包含瓶颈清单**，只报「通过/不通过」的报告没有价值。

## 三、演练体系

### 3.1 三级演练

| 级别 | 形式 | 频率 | 产出 |
|---|---|---|---|
| 桌面推演 | 对照架构图走流程、核对联系人 | 月度 | 「预案里缺了哪一步」清单 |
| 切换演练 | 主备切换、双活切流，真实执行 | 季度 | 切换耗时、数据一致性校验报告 |
| 混沌注入 | 延迟/错误/实例故障注入 | 半年起 | 系统与人的真实反应记录 |

### 3.2 演练即生产（强制）

演练必须走正式变更流程：

- 有变更单、有通知、有观察窗口、有回滚预案；
- 演练失败的处置与真实事故相同（复盘 + 行动项）；
- **不许「为了演练顺利」而跳过步骤**——那是演给自己看。

### 3.3 混沌演练的渐进路径

```
单实例故障 → 单依赖超时/错误 → 单机房不可用 → 区域切换
```

每级通过后再进下一级。注入的故障类型按「生产真实发生过、或最可能发生」排序，不为了酷而注入。

## 四、演练记录模板

| 项 | 内容 |
|---|---|
| 演练编号 / 日期 | DR-YYYYMMDD |
| 级别 | 桌面 / 切换 / 混沌 |
| 场景 | 注入什么故障，预期系统如何反应 |
| 参与角色 | 指挥者 / 操作者 / 观察者 |
| 预期恢复时间 | __ 分钟 |
| 实际恢复时间 | __ 分钟（**与预期的差值就是预案的水分**） |
| 数据一致性 | 切换前后核对方式与结果 |
| 发现的问题 | 预案缺陷 / 系统缺陷 / 人的问题 |
| 行动项 | owner + deadline，与事故复盘同一张台账 |

## 五、与治理的衔接

- 容量见底时间进入 [组合治理](../../system-portfolio-governance/00-methodology.md) 的年度盘点输入；
- 长期无演练的系统，视为「运维健康度」不达标，进入治理诊断的低健康象限；
- 演练发现的系统缺陷，按 P0–P3 进入 [诊断卡](../../system-portfolio-governance/templates/02-system-diagnosis.md) 的问题台账。

## 六、自检清单（季度）

- [ ] 容量模型是否更新？瓶颈排序表是否包含见底时间？
- [ ] 是否至少做过一次切换演练？实际恢复时间与预期的差值是否收敛？
- [ ] 压测报告是否包含瓶颈清单与限流验证？
- [ ] 演练是否走了正式变更流程？有无「演练专用绿色通道」？
- [ ] 混沌演练是否按渐进路径推进（没有跳级）？
- [ ] 演练发现的问题是否全部进入行动项台账并闭环？
