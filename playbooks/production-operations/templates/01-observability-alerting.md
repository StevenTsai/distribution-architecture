# 模板 01：可观测性与告警规范

> **能力域**：观测 ｜ **配套**：[00 方法论 §三](../00-methodology.md) ｜ **产出**：四层信号清单 + 告警规则表 + 值班表 + runbook 库

---

## 一、四层信号清单

### 1.1 指标体系（强制，先建业务指标）

| 类别 | 指标（示例，按系统取核心项） | 采集方式 | 基线/阈值 |
|---|---|---|---|
| 延迟 | 核心接口 P50 / P99 | APM / 网关日志 | P99 > 基线 50% 持续 5 分钟 |
| 流量 | QPS / 订单量 | 网关 / 业务埋点 | 同比下跌 > 30% |
| 错误 | 错误率 / 5xx 率 | 网关 / 日志聚合 | 错误率 > 1% 持续 3 分钟 |
| 饱和度 | CPU / 连接池 / 队列深度 / 磁盘 | 主机与中间件监控 | 使用率 > 80% 持续 10 分钟 |
| **业务** | 支付成功率 / 登录失败率 / 核心转化环节 | 业务埋点 | 跌破 __%（**优先建这一层**） |

### 1.2 日志（强制）

- 结构化（key=value 或 JSON），含 traceId；
- 级别纪律：ERROR 必须可行动（每条 ERROR 对应一次排查或一次忽略决策）；INFO 不打循环内高频日志；
- 保留期分级：热查 7–30 天，冷备按合规要求。

### 1.3 链路追踪（推荐，核心链路强制）

- 覆盖关键入口 → 关键依赖的完整路径；
- trace 采样率与成本平衡；关键链路覆盖率目标 ≥ 90%。

### 1.4 外部依赖健康（强制）

| 依赖 | 探活方式 | 告警阈值 | 降级开关 |
|---|---|---|---|
| 支付渠道 | 主动探活 + 成功率 | 成功率 < __% | 有无 |
| 短信/推送 | 发送成功率 | < __% | 有无 |
| 第三方 API | 延迟 + 错误率 | P99 > __ms | 有无 |

## 二、告警规则表（每条四要素缺一不可）

| 告警名 | 层级 | 分级 | 判据 | 责任人 | runbook | 抑制/聚合规则 |
|---|---|---|---|---|---|---|
| 支付成功率跌破 | 业务 | P1 | < 99% 持续 3 分钟 | 值班 SRE | runbook/payment.md | 上游渠道故障时抑制 |
| 核心接口 P99 超基线 | 指标 | P2 | > 基线 50% 持续 5 分钟 | 服务负责人 | runbook/latency.md | 同源合并 |
| 连接池耗尽 | 指标 | P2 | 使用率 > 90% 持续 5 分钟 | 服务负责人 | runbook/pool.md | — |

### 分级定义

| 级 | 定义 | 响应要求 |
|---|---|---|
| P1 | 用户可感知的大面积功能不可用或资金错误 | 5 分钟内响应，立即拉群，指定指挥者 |
| P2 | 部分功能受损 / 单渠道故障 / 容量逼近上限 | 15 分钟内响应，当班处理 |
| P3 | 冗余丢失、非核心异常、趋势性恶化 | 当日处理 |
| P4 | 趋势提醒 | 周会评审，不打扰值班 |

### 降噪三件套（强制）

1. **聚合**：同源多实例告警合并为一条；
2. **抑制**：上游根因告警触发时，抑制下游派生告警；
3. **静默**：计划内变更窗口内静默相关告警（静默必须有截止时间和负责人）。

> 无主告警视为缺陷：每月清理一次「没有责任人」或「连续 30 天无人处置」的告警——**没人能行动的告警，会训练所有人忽略告警**。

## 三、值班与升级

| 项 | 规则 |
|---|---|
| 轮值 | 按周轮换，交接时同步：进行中的告警、计划的变更、已知风险 |
| 响应时限 | P1 5 分钟 / P2 15 分钟未响应 → 自动升级到备份值班 |
| 升级路径 | 值班 → 服务负责人 → 技术负责人（写清联系方式与时间阈值） |
| 夜间纪律 | P1/P2 才允许夜间唤醒；P3/P4 进白天队列 |

## 四、runbook 最小结构

每条告警对应一页，四段式：

```
1. 现象：告警长什么样、影响什么
2. 判断：3 步内确认（看哪个面板/哪条日志）
3. 止血：首选动作（回滚/降级/切流），以及动作的副作用
4. 升级：什么条件下找人、找谁
```

runbook 写不出来的告警，说明这条告警还不该上线。

## 五、自检清单（季度）

- [ ] 业务指标告警是否覆盖核心链路？用户投诉是否仍是第一发现渠道？
- [ ] 每条告警是否四要素齐全（责任人/分级/判据/runbook）？
- [ ] 过去 90 天是否有「响过但无人处置」的告警？是否已清理或补 runbook？
- [ ] 告警总量是否在增长？聚合与抑制规则是否随新服务更新？
- [ ] 值班交接记录是否完整（进行中告警/计划变更/已知风险）？
- [ ] 外部依赖的健康告警与降级开关是否一一对应？
