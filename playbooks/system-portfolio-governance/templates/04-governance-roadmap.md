## 二、防回潮三道闸门

### 闸门 1：新建准入

| 项 | 内容 |
|---|---|
| 规则 | 新系统立项必须先在组合清单占一行 |
| 立项表必填 | 分配系统 ID / 声明角色（五分类）/ 与既有系统的关系（新建·替换·并存）/ 为什么不是给现有系统加模块 |
| 卡点载体 | 立项申请表单（无清单行号不受理） |

### 闸门 2：依赖准入

| 项 | 内容 |
|---|---|
| 规则 | 引入新中间件 / 框架 / 外部服务，过一次轻量架构评审 |
| 评审纸面（≤1 页） | 使用场景 / 备选（含「不用」）/ 退出成本（换掉要改什么）/ 运维要求 |
| 豁免 | 仅单系统内部使用且不入库的纯开发期工具 |

### 闸门 3：下线默认

| 项 | 内容 |
|---|---|
| 规则 | 连续 12 个月无发布 **且** 0 依赖方的系统，**自动**进入下线复审 |
| 执行方式 | 脚本按月扫描组合清单，命中项直接生成复审任务（不需要任何人提议） |
| 复审输出 | 一条模板 03 决策记录（关停 / 降配 / 例外保留——例外保留也必须留痕并注明复审日） |

> **需要人自觉的闸门不是闸门。** 三道闸门都必须有流程卡点或脚本，倡议书不算。

## 三、季度自检表

每季度治理例会前，负责人对照勾选：

- [ ] 组合清单全部字段刷新至本季度（E5 行不超过 5%）
- [ ] 上季度路线图逐条对账：完成 / 未完成（未完成的写明原因并重排，不许静默顺延）
- [ ] 新建系统 100% 先入册后立项（闸门 1 违规数 = 0）
- [ ] 新增中间件/外部服务 100% 有评审记录（闸门 2）
- [ ] 下线默认扫描已运行，命中项已生成复审任务（闸门 3）
- [ ] 本轮是否产生了至少一条处置决策？（若无 → 复盘盘点本身，见 [原则一](../00-methodology.md#二四条原则)）
