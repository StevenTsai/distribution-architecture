# 模板 02：单系统诊断卡（System Diagnosis Card）

> **阶段**：诊断 ｜ **触发**：进入处置决策前 / 连续故障复盘后 / 年度盘点抽样 ｜ **配套**：[00 方法论 §四](../00-methodology.md)
> 原则：**全量清点，重点诊断**。不必给每套系统都建诊断卡——休眠候选、P0 故障户、成本前三优先。

## 二、四层诊断清单

每层逐项检查，勾选并记录发现。**无发现的层也要写「未见异常」**——空白等于没查。

### 2.1 领域层

- [ ] **重复建设**：是否存在另一套系统存有同类权威数据？冲突时以谁为准？
- [ ] **越界**：是否在干相邻域的活（本域系统实现了别域的规则）？
- [ ] **空心**：核心逻辑是否已迁走，只剩转发/透传？
- [ ] **主数据地位**：本系统是哪些数据的唯一权威源？

| 发现 | 层内问题 | 关联系统 | 证据 |
|---|---|---|---|
| | | | |

### 2.2 架构层

- [ ] **单点**：核心组件（库/队列/关键实例）有无冗余与预案？
- [ ] **循环依赖**：是否与其他系统存在双向调用？
- [ ] **一致性机制**：跨系统数据靠什么保证一致（事务/对账/最终一致）？有无兜底？
- [ ] **接口契约**：对外接口有无版本化与变更通知机制？

| 发现 | 问题 | 证据 |
|---|---|---|
| | | |

### 2.3 工程层

- [ ] **构建可复现**：新人按文档能否独立构建并启动？
- [ ] **测试基线**：有无自动化测试？覆盖关键路径吗？
- [ ] **关键人集中**：有几个人能独立做生产变更？
- [ ] **文档新鲜度**：架构图/README 距最近一次发布多久？

| 发现 | 问题 | 证据 |
|---|---|---|
| | | |

### 2.4 运维层

- [ ] **监控覆盖**：核心链路有无告警？告警有人接吗（演练过吗）？
- [ ] **容量余量**：峰值余量多少倍？见底时间点？
- [ ] **成本效率**：资源利用率区间？有无「峰值 10 倍余量」式浪费？
- [ ] **备份可恢复**：最近一次恢复演练是什么时候？

| 发现 | 问题 | 证据 |
|---|---|---|
| | | |
