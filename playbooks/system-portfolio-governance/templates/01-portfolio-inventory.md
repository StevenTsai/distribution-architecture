## 二、字段填写规范

### 2.1 角色五分类（必选其一，定义见 [§3.1](../00-methodology.md#31-角色五分类每套系统必须归一类)）

记录型 ｜ 流程型 ｜ 门户型 ｜ 集成型 ｜ 工具型

### 2.2 状态

| 值 | 定义 |
|---|---|
| 活跃 | 近 6 个月有需求发布 |
| 维护 | 无需求发布，但有故障响应与安全更新 |
| 休眠 | 12 个月无发布、无故障（可能无人在看） |
| 待下线 | 已有决策记录（关联模板 03 编号） |

### 2.3 数据等级

**核心**（权威数据，关停需迁移方案）｜ **一般**（有副本或可重建）｜ **脱敏/衍生**（可重算，关停只需归档）

### 2.4 证据等级（[00 方法论 §3.4](../00-methodology.md#34-证据分级与接手工程同源)）

**E1** 监控/发布系统实测 ｜ **E2** 账单/工单记录 ｜ **E3** 系统文档 ｜ **E4** 负责人访谈 ｜ **E5** 推断

## 三、数据来源清单（取数渠道备忘）

| 字段 | 权威来源 |
|---|---|
| 最近发布 | 发布系统 / CI 流水线记录 |
| 90 天故障数 | 告警平台 + 工单系统（去重后按事件计） |
| 依赖方数 | API 网关路由表 + 调用链追踪（取「被调用」方向） |
| 月成本 | 云账单按标签分摊；无标签的均摊后标注 E5 |
| 维护人力 | 近 3 个月工时记录；无记录取负责人自报（E4） |

---

## 四、维护规则

1. **唯一权威源**：组合清单只有一个版本、一个位置、一个负责人（治理角色，非系统负责人）；
2. **即时入册**：新系统立项未占行的，不批预算（防回潮第一闸门，[§七](../00-methodology.md#七防回潮三道闸门)）；
3. **季度刷新**：活跃度与成本字段每季度全量刷新一次，其余字段变更即改；
4. **E5 限期清零**：E5 行超过一个季度未补证的，视为该系统的「治理失职」上报架构委员会。
