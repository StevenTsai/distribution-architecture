# 声明级校验门：把不可信输出降维成可判定的断言

> 整段打分只能得到"相关性"，主张级校验才能得到"这条能不能交付"。
> 粒度决定可验证性。

---

## 一、问题：整段评分拦不住夹带

传统 RAG 评测和护栏大多作用在"段落"粒度：给回答和检索结果算一个相关性分数，超过阈值就放行。

这个粒度有一个结构性盲区：**一段话可以处处像检索结果，同时夹带编造。** 相关性分数是全局的，幻觉是局部的。用全局指标拦截局部缺陷，就像用平均体温判断病人有没有一处骨折。

把回答降维：

```
回答（一段自然语言）
  └─▶ AnswerClaim[]（一条 = 一个可独立判定的断言）
        每条声明绑定 EvidenceId[]（证据锚点）或 RuleDecision[]（权威规则）
```

一条主张要么有据可验，要么无据降级（关键主张拒答、非关键降为标注）。**"看起来像真的"在这个粒度上不再是一个可交付的状态。**

---

## 二、模式结构

```mermaid
flowchart TB
    A[LLM 输出] --> C[AnswerClaim[]<br/>原子化主张]
    C --> B[绑定<br/>EvidenceId[] / RuleDecision[]]
    B --> G1[① 引用完整性]
    G1 --> G2[② 表面一致性]
    G2 --> G3[③ 规则冲突裁定]
    G3 --> G4[④ 证据充分性]
    G4 --> R{判决：按主张关键性分流}
    R -->|锚点完整且一致| P[PASS<br/>原样交付]
    R -->|可交付但需标注| N[ANNOTATE<br/>带免责声明]
    R -->|失败·非关键主张| N2[ANNOTATE<br/>附"未经本地证据核验"]
    R -->|失败·关键主张| X[REFUSE<br/>拒答或删除该条]
```

四步门全部是**纯逻辑**，零 LLM 依赖。校验器本身必须是确定性的，否则只是把不可信换了个位置。

证据来源：[GroundedRAG](https://github.com/StevenTsai/grounded-rag) 的 `guardrail` 模块（`claims.py` 原子化、`verifier.py` 四步门、`evidence.py` 锚点绑定），[可 clone 复现](#证据与复现)。

---

## 三、四步门

### ① 引用完整性

判定：每条主张的 `evidence_refs` / `rule_refs` 是否存在、可解析、指向库内真实条目。

拦的是"声称有据但锚点悬空"。放在第一步的原因是**顺序不可换**：没有可解析锚点的内容比对没有意义，先做后面几步只会浪费判定并污染统计。

### ② 表面一致性

判定：主张中的实体、数值、单位是否**字面出现在**所引证据的原文（text_span）内。

刻意只做表面（surface）不做语义：字面出现与否是可判定的，语义蕴含不是。这一刀切掉了"相关性打分"的全部模糊地带（代价见第六节的能力边界）。

### ③ 规则冲突裁定

权威规则之间互相打架时，裁定顺序是固定的：

```
过滤 stale 版本 → 取最高 grade → 取最新 updated_at → 仍冲突则声明分歧
```

多数系统的默认动作是静默二选一，因为产品上不接受"两个都对"。但在医疗、金融、合规场景，静默二选一是更大的风险：两个 A 级权威各说各话时，系统应该把分歧本身作为输出交付，让人来裁。所以最后一步是**"承认无法选"**。

适用前提：冲突只在"同一条件域 + 方案集合互斥"上裁定；grade 语义必须全库统一，否则整个裁定顺序没有意义。

### ④ 证据充分性

判定：锚定的证据是否**足以支撑**这条主张的存在（而非仅不矛盾）。

过完四条，产出三态判决而不是二态：PASS 原样交付 / ANNOTATE 交付但标注 / REFUSE 拒答。失败路径按主张关键性分流：**关键主张 REFUSE，非关键主张降为 ANNOTATE**（展示时附"未经本地证据核验"；参考实现中每条失败路径都是 `REFUSE if effective_critical else ANNOTATE`）。三态要解决的问题是："可交付但置信边界要暴露"和"不可交付"是两件不同的事，二值化会把中间态全部推到某一侧。

## 四、两条不变量

四步门是流程，不变量是流程**防不住时的兜底**。

### 4.1 同源不变量：反跨证据拼装

规则（v1.0.0 实现口径）：主张中的**数字必须全量**落在**同一条**证据的 text_span 里；**实体按表面命中比例**（`element_ratio`，默认 0.5）落在同一条证据里；规则侧另设 `max(0.75, element_ratio)` 高门槛，不能拿一条"等级高但内容不符"的规则凑等级。

它防的是**跨证据拼装**，RAG 里较难自查的一类幻觉：

```
文档 A 的实体 + 文档 B 的数字 + 文档 C 的等级
  → 一个"处处有据"、整体为假的答案
```

普通引用检查完全拦不住：每个引用单独看都是真的。同源不变量把判定单位从"引用集合"收紧到"单条证据内的锚定"。

边界（必须知道）：它只防拼装，不防"同源但语义反向"。后者依赖证据侧的否定检测补丁（如否定词窗口），那是启发式：长句、复杂句式会漏。

### 4.2 单调权限：元数据不可信，授权只能收紧

规则：

```
effective_critical = claim.critical  OR  is_critical_claim(text, type)
```

- 模型可以把一条主张**升级**为"关键"，升级无害；
- 模型**不能降级**。主张自标"非关键"时，表层词表（高风险表述的强制识别）会覆盖它；
- LLM 自报的 type 字段一律视为不可信元数据，以词表判定为准。

推广出去，这是一条通用原则：

> **对不可信输入的授权应当是单调的——只能收紧，不能放松。**

权限系统、风控标记、内容审核同理。大量系统的漏洞出在"相信了模型/外部输入说自己不重要"。允许 LLM 自报"非关键"来绕过强校验，关键性判定就不再成立。

边界：词表覆盖有漏；换域必须重写词表，否则"关键"判定会漂移。

## 五、grade 的正确语义

`grade` 是**推荐强度**（权威等级），不是**证据充分性门槛**。

两者的混淆是一个常见设计错误：把低等级推荐判为"证据不足"而拒答。正确的处理是：C 级推荐照常输出，把等级一并展示。"这条建议权威性一般"和"这条建议没有依据"是两个正交维度：

| | 有据 | 无据 |
|---|---|---|
| 高推荐强度 | 直接交付 | 拒答 |
| 低推荐强度 | 交付并展示等级 | 拒答 |

把"低强度"误判为"不可回答"，会让系统性地沉默掉大量本来合法的弱建议。

## 六、能力边界（诚实区）

模式的边界和用法一样重要。以下边界在参考实现里都有对应代码或文档可查，先写清边界再谈用法：

1. **表面一致 ≠ 语义支持。** 一个字面出现在证据里、语义上却与主张方向相反的数值，表面一致性检查会通过。方向性主张（否定、比较、因果）在语义档关闭时无法验证：关键主张拒答，非关键降为标注（源码口径是"拒答或标注"，不是一律拒答）。这是诚实的降级，代价是 v1.0 在高价值语义空间里可交付的部分近乎为空；
2. **实现依赖上下文抽取。** 参考实现的规则引擎对缺失字段直接判 False（静默不命中），没有 skip 语义（缺失 ≠ 假）。规则直出的覆盖率高度依赖上下文抽取器，而其抽取器偏医疗启发式。机制可移植，适配器要重写；
3. **词表与阈值是领域资产。** 关键词词表、匹配阈值（0.75）、否定窗口，换域都要重标定；
4. **指标口径不可打包。** 引用完整性、表面一致率、拒答正确率三者各管一段，合并称"准确率"即夸大能力边界（详见[失败复盘篇](verifier-failure-modes.md)的双口径制度）。

## 七、什么时候值得上这个模式

| 场景 | 判断 |
|------|------|
| 输出直接进入高风险决策（医疗/金融/法务/合规） | 值得。幻觉成本 >> 校验成本 |
| 输出面向公众但有人工兜底 | 半值得。主张绑定 + 引用完整性两步即可，四步门可裁剪 |
| 低风险问答、幻觉成本低 | 不值得。整段引用 + 人工抽检更经济 |

渐进路径（每步独立产生价值，随时可停）：

```
① 主张原子化 + 锚点绑定 → ② 引用完整性门 → ③ 表面一致性门
  → ④ 权威冲突裁定 → ⑤ 语义档（永远是最后一档，成本最高）
```

第①步做完就能回答"这条能不能溯源"；大多数团队在②③就已拿到主要收益。语义档不要提前建：它是所有步骤里唯一无法给出确定性承诺的。
